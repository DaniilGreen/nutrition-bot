**Найдено:** в живом каталоге **29 групп дублей**, накопившихся уже после разовой миграции 0008
(«Творог 5%» / «творог 5%», «Макароны отварные» / «отварные макароны» и так далее). Значит
рантайм продолжает их плодить — миграция чинила прошлое, но не будущее. Теперь слияние доступно
из аппки, а группировка живёт в домене и переиспользуема.

**Решение по опасным группам:** где разброс плотности выше 15%, слияние не блокируется, но
помечается предупреждением с числом («разошлись на 21%»). Автоматически такие не сливаем —
политика владельца из D-32.

## Этап MA-M5 — аналитика (§8.6)

| # | Что входит | Статус | Чем проверено |
|---|---|---|---|
| M5.1 | `StatsService.last_days_macros` — ряд по дням одним запросом | DONE | 11 e2e, `tests/e2e/test_api_stats.py` |
| M5.2 | `GET /api/stats/series` — один эндпоинт на все графики | DONE | e2e: порядок, пустые дни, чужое не видно |
| M5.3 | `GET /api/stats/weight` — замеры, мусорные отсекаются | DONE | e2e: «915» вместо 91,5 не ломает масштаб |
| M5.4 | Фронт: пять графиков инлайн-SVG, без библиотек | DONE | скриншот |
| M5.5 | Переключатель периода: неделя · 30 дней · 3 месяца | DONE | вёрстка |

**Производительность:** прежний `last_days` ходил в БД по разу на день — тридцать round-trip'ов
ради одного месячного графика. Новый метод берёт окно одним `list_between` и группирует
по локальной дате в питоне. Группировка именно по локальной: иначе ужин в 23:30 уехал бы во вчера.

**Геометрия графика:** столбики и линия цели считаются в ОДНОМ масштабе. Раньше в макетах
это разъезжалось — «зелёный» столбик оказывался выше линии цели, и график врал глазу.
Перебор рисуется отдельным сегментом сверху с хайрлайном цвета фона: граница читается
не только цветом (WCAG 1.4.1).

**Ключевое:** лимит проверяется **до** вызова модели. Проверка после означала бы «превысил —
узнал», то есть лимит, который ничего не ограничивает. Тест это фиксирует: при исчерпанном
бюджете `seen_facts` у стаба остаётся `None` — модель не дёргалась вовсе.

**Неизвестная модель считается по дорогому тарифу** (`DEFAULT_PRICE`): ошибаться в учёте денег
надо в свою сторону, а не в сторону провайдера.

**Область лимита** уточнена решением D-MA-3: только вкладка AI. Отказ записать съеденное
из-за исчерпанного бюджета нарушил бы D-28 («провал — это не записать»).

| # | Что входит | Статус | Чем проверено |

| S.2 | `app/domain/prefs.py` — белый список ключей и значений | DONE | `python -m app.domain.prefs` |
| S.3 | `GET /api/settings` — всё одним запросом | DONE | 21 e2e, `tests/e2e/test_api_settings.py` |
| S.4 | `PATCH /api/settings/prefs` — частичная правка | DONE | e2e: мусор отбрасывается, остальное не сбрасывается |
| S.5 | `PATCH /api/settings/goal` — цели, включая белок в г/кг | DONE | e2e: 2,0 г/кг × 91,5 = 183 г |
| S.6 | `PATCH /api/settings/timezone` — с проверкой значения | DONE | e2e: «Марс/Олимп» → 400 |
| S.7 | Фронт: шестерёнка в шапке, четыре группы | DONE | скриншот |

**Почему JSONB, а не колонка на пункт:** восемь миграций ради настроек, которые вообще
не влияют на данные — только на то, как эти данные нарисованы. Цели и часовой пояс сюда
НЕ кладём: у них своя семантика, они меняют расчёты.

**Белый список обязателен:** `ui_prefs` это JSONB, куда клиент шлёт произвольный объект.
Без списка туда уедет что угодно, включая мегабайт мусора в строке пользователя.

**Найдено по дороге:** маршрут настроек лез в `SqlSpendRepo` напрямую — нарушение MA-INV-5.
Вынесено в `Container.spend_for`. И ошибки разбора тела отдавались схемой FastAPI (422) мимо
конверта §7.4 — фронту пришлось бы разбирать два формата ошибок. Теперь один.

### Оформлено решением, не починено

- **D-MA-4** — часть эндпоинтов §7.2 слита; лишние round-trip'ы дороже толстых ответов.
- **D-MA-5** — невозможная плотность отвергается, а не зажимается: тихая правка на границе
  доверия хуже отказа.

### Закрыто следом

- **A3.** Оформлено решением **D-MA-6**: каталог общий, слияние доступно обоим и
  необратимо. Интерфейс обязан назвать число затрагиваемых позиций и предупредить,

- **F1.** Заведён `tests/sql/` — 7 тестов на **настоящем Postgres**: экранирование `%`

  без движения снапшота, медиана через `percentile_cont`, склейка чипов после слияния,
  доля оценок по калориям. Без БД набор пропускается, поэтому `make test` локально
  не требует её. В CI поднимается сервис `postgres:16-alpine`.
- **F7.** Фронт в гейте: `node --check web/app.js` плюс проверка, что все три файла
  на месте. Сломанный `app.js` кладёт аппку целиком, а бот при этом жив — деплой

### Не сделано и почему

**Пуш site-блока в репозиторий `finance-bot`.** Код написан, лежит на сервере
(`/opt/finance_bot`, коммит `ec2b52b`) и проходит `caddy validate`, но **не отправлен
в GitHub**: оба SSH-ключа на сервере read-only, а с рабочей машины DNS до github.com
отваливается. Пока коммит не уйдёт в `origin/main` соседнего репозитория, их следующий
деплой (`git reset --hard origin/main`) вернёт файл к прежнему виду, и аппка перестанет
открываться. Это единственное, что отделяет её от прода.
