## 1. Цель

Перевести самые частые сценарии бота на HTML-виджеты Telegram (Bot API 10.4, 9.11.2026) так, чтобы:
- частые действия стали быстрее — меньше сообщений и тапов на одну запись;
- графики стали настоящими (SVG / canvas) вместо баров символами и последнего PNG;
- виджеты выглядели как продолжение Mini App — те же смыслы цветов, иерархия, токены;
- точность учёта КБЖУ — главный приоритет проекта — не пострадала ни на грамм.

Результат ночи — код в проде за флагом, зелёные тесты, обновлённая спека и утренний отчёт.

|---|---|---|

Вызовов модели за 30 дней: разбор 824, vision 424, голос 58, ассистент 4.

Выводы для приоритета:
- **После каждой записи** человек видит карточку приёма — это самый частый экран после ввода.
- **«Частое»** — каждая пятая запись владельца: один тап вместо пикера даст ощутимую скорость.
- **Подтверждение разбора** (S/M/L, количество) — цепочка сообщений на каждой неоднозначной записи.
- Ассистент почти не используется — виджеты для него последними.
- Продуктовый аналитик **сначала перепроверяет эти цифры** по базе и дополняет: сколько уточнений
  на запись, сколько правок граммов после записи, сколько раз открывают «Сегодня» / «Неделю»
  (если это видно в логах или callback-данных), сколько дней недозаписаны.

## 5. Объём ночи — по волнам, строго по порядку

Каждая волна — законченный кусок: спека → код → тесты → деплой → проверка в проде. Не начинай
следующую, пока предыдущая не зелёная в проде.

**Волна 0 · фундамент (обязательно)**
1. Спайк транспорта: `sendWidget`, `editMessageWidgetData`, `answerWidgetQuery` через свой
   подкласс `TelegramMethod` aiogram (или прямой POST). Проверь, есть ли релиз aiogram с 10.4 —
   обновляй, только если он вышел и тесты зелёные; иначе свой метод.
2. Приём апдейта `widget_query` при поллинге: добавь тип в `allowed_updates`, проверь на живом
   боте, доходит ли апдейт до хендлера в aiogram 3.31. Не доходит — разбери сырой апдейт сам
   (middleware / `feed_raw_update`). Запиши результат в OQ-W1.
3. Реестр шаблонов: `app/bot/widgets/<имя>.html` + сборщик `chat_data` в `app/bot/ui/` рядом
   с rich-экранами, данные — из тех же `gather()` / сервисов (MA-INV-1).
4. Тест бюджета в гейте (W-INV-3): каждый шаблон ≤ 4096 байт после `zlib.compress(..., 9)`;
   каждый `chat_data` ≤ 1024 байт на худших реальных данных (день с 20 приёмами, длинные имена).
5. Флаг раскатки: `WIDGETS_USERS` (по умолчанию — только владелец). Остальные видят rich.
6. Фолбэк (W-INV-2, D-43): `sendWidget` / `edit…` упал → прежний rich-экран, ошибка в лог.

**Волна 1 · «📊 Сегодня» виджетом (решено, D-43)**
- Одно сообщение на день; после каждой записи / правки / удаления — `editMessageWidgetData`,
  а не новое сообщение. Новый день — новое сообщение.
- Внутри: герой КБЖУ как в «Дне» аппки (§6.2), лента приёмов (≤ 600 px — топ-N + «ещё N»),
  тап «съедено / осталось», точность дня (доля ≈-оценок, §3.5 MA), кривая «темп против нормы»
  из §6.20 (две линии: сегодня и личная медиана к часу).
- Кнопка «📱 Открыть в приложении» → `openTelegramLink` / inline-кнопка FR-46 на экран «День».
- Подпись (caption) — главная цифра дня текстом.

**Волна 2 · действия (нужны запросы из волны 0)**
- Карточка приёма после записи (FR-12/13/41/43/44): позиции, ±10 г, удалить позицию, «Вернуть».
- «Частое» в один тап (FR-40): сетка частых продуктов и наборов, тап → запись, хаптик, «Вернуть».
- Подтверждение разбора (FR-4/5/20/21): позиции, ±граммы, S/M/L чипами, «Записать» запросом.
  Предпросмотр КБЖУ в JS = граммы × запиннутая плотность из `chat_data`; истина — ответ бота
  (W-INV-1). `resolve_grams`, Атвотер, пиннинг в JS НЕ повторять.

**Волна 3 · графики (если время осталось)**
- «⚖️ Вес» на SVG (FR-8, D-40: только записанные значения, без сглаживания) — удалить последний PNG
  и его рендер, если зависимость больше никому не нужна.
- «📈 Неделя» (FR-48, D-39): число недели героем, бары ккал и белок, тап по дню — разбор.
- Вечерний итог (FR-18) с кнопками «✅ всё записал / ➕ забыл» — сигнал полноты дня.

**НЕ делать этой ночью:** утренний чек-ин со сном и тренировками (#18 — меняет scope SPEC §4,
нужен владелец), онбординг, ассистент графиком. Оставь их в каталоге с оценкой.

## 6. Дизайн — преемственность с аппкой

- Смыслы цветов — из MA-INV-20: «в цели» / «отстаёт» / «перебор» — только статус; нутриенты —
  свои цвета макросов из §6.16 и никогда не статус. Цвет «для живости» не добавлять.
- Аппка тёмная, а чат бывает светлым: фон и текст — из `--tg-theme-*`, акценты — пары
  `light-dark(светлый, тёмный)` от токенов аппки, контраст ≥ AA (§6.17) в обеих темах.
- Иерархия «Дня» аппки: герой → макросы → лента; подписи и числа как в аппке (`tabular-nums`).
- Проверка вёрстки — на ширинах 200 px и максимум пузыря (~420 px), в светлой и тёмной теме,
  высота ≤ 600 без скролла (W-INV-7/8). Это аналог правила 320/1100 из CLAUDE.md §5.1.
- Мутация не стирает экран (MA-INV-32 → W-INV-6): busy-состояние на кнопке, остальное на месте.
- Только то, что входит в профиль 1 виджетов: без `input`, `vh`, `oklch`, `:has`, `clip-path`,
  `text-shadow`, внешних ресурсов и сети. Всё недопустимое Telegram молча вырезает — значит,
  ошибку не увидишь, пока не проверишь рендер.

### 6.1 Планка качества — витрина Telegram, а не дефолтные кнопки

Открой и посмотри: `docs/prompts/refs/tg-weather.png`, `tg-delivery.png`, `tg-word-game.png` —
промо-виджеты Telegram к 10.4. Это уровень, на который целимся. Демо 10.11 (`<button>` по
умолчанию, бары на сером) — нижняя граница, не образец.

Что у них взять и как переложить на burnfat:

| Приём в примере | У нас |
|---|---|
| Погода: своя заливка на весь пузырь, огромное «24°» героем, строка «по часам» с выделенным текущим часом | «Сегодня»: калории героем крупно, под ним «осталось · белок %»; лента «по часам» — чипы часов с приёмами, тап по часу → что съедено |
| Доставка: карта нарисована CSS-блоками (настоящих тайлов нет — сети нет), живой статус, шаги «Placed → Cooking → On the way → Delivered» сегментами, метка «Live» | Живая карточка дня: сегменты приёмов «завтрак · обед · перекус · ужин» с заполнением; после записи бот обновляет — короткая подсветка «обновлено» |
| Слово дня: сетка плиток со статусами, 🔥-счётчик серии | Месяц «полнота записей» — плитки дней: цвет = статус цели (MA-INV-20), пунктир = недозаписан; 🔥 серия записанных дней с заморозкой (D-44) |
| Игра: canvas, анимация, отклик на тап | Анимация роста баров и счёт цифр при открытии (`prefers-reduced-motion` уважать), хаптик на тапы, кривая «темп против нормы» на canvas / SVG |

Чего у них НЕ брать:
- Серию по «дням в цели» — только по полноте записей (D-44).
- «Share results» — в проде виджеты нельзя переслать (protected content).
- Картинки-иллюстрации — в 4 КБ после zlib не влезут; объём и глубина — CSS-градиентами
  (linear / radial / conic), тенями `box-shadow` и inline SVG.

Технически под это: своя подложка карточки разрешена, но текст на ней проверяй на контраст в обеих
темах чата; кольца — `conic-gradient`; плавность — transitions / `@keyframes` / Web Animations.
Бюджет 4 КБ съедается быстро: общий CSS — один раз, повторяющееся — генерировать из JS по данным.

## 7. Роли

- **Разработчик.** Пишет код волнами, маленькими коммитами; каждый шаг — с тестом.
- **Продуктовый аналитик.** Перед стартом — замер из §4 и базовые метрики: записей в день, сообщений
  и тапов на одну запись, доля уточнений, доля недозаписанных дней. Ставит цель каждой волне
  («Частое: тапов на запись было N, стало 1»). После — что можно измерить сразу, что через неделю.
  Новая таблица событий — только если описана в SPEC и миграция аддитивная.
- **Аналитик спеки.** До кода каждой волны — FR / AC / W-INV в `SPEC.md` и `MINIAPP-SPEC.md`,
  перенос W-INV из `WIDGETS.md` в спеку по мере реализации. Код без записи в спеке — недоделка.
- **Тестер.** Юнит-тесты сборщиков `chat_data` и разбора `widget_query` (формат, чужой владелец →
  отказ, повтор → не пишет дважды); тест бюджета; рендер-проверка в браузере с официальной
  заглушкой `TelegramWidget` (200 / 420 px, светлая / тёмная), скриншоты в отчёт; живой прогон
  в Telegram (§8). Ищет регрессии в rich-экранах, которые остались.
- **Ревьюер.** Перед каждым пушем — независимое ревью диффа на W-INV, безопасность границы
  `widget_query`, точность чисел. Находка «блокер» — фикс до пуша.

## 8. Ограждения — нарушать нельзя

- **Прод — VPS.** Деплой = пуш в `main` → GitHub Actions (тесты — гейт). Проверяй по хэшу: на
  сервере `git log -1` в `/opt/burnfat` и свежий старт контейнера `bot`. Статус прогона в API GitHub
  бывает устаревшим — сверяй с сервером. Красный прогон = не задеплоено.
- **Не поднимать бота локально** (`make up`): токен общий с продом → `Conflict`, прод ляжет.
- Тесты: `docker compose run --rm --no-deps -v "$PWD/tests:/app/tests" -e DATABASE_URL= api pytest -q`.
  На сервере pytest — только с пустым `DATABASE_URL` (иначе тесты видят прод-базу).
- **Живые проверки в Telegram — только в чат владельца** (`OWNER_TELEGRAM_ID` из `.env` на
  сервере), с `disable_notification: true`, и удалять тестовые сообщения после проверки. Второму
  пользователю ночью ничего не слать: флаг `WIDGETS_USERS` = только владелец.
- Перед коммитом: `git ls-files --error-unmatch .env` должно падать. Секреты не печатать.
- Коммиты: `type(scope): subject`, крупным — `#comment` на русском 18–30 слов; без упоминаний
  Claude и `Co-Authored-By`; без Jira-ключа. Чужой неотслеживаемый файл (`AGENTS.md`) не добавлять.
- База: только аддитивные миграции; никаких `DELETE` / `UPDATE` по прод-данным владельца и
  второго пользователя. Ничего не удалять из каталога продуктов.
- Диск сервера 10 ГБ: не трогать `requirements.txt` / `Dockerfile` без нужды (пересборка);
  `docker image prune -a` — запрещено.
- Деньги: eval NLU не гонять — виджеты разбор не меняют. Если всё же тронул разбор — сабсет, ≤ $3.
- Не трогать finance-bot.
- Застрял: тот же шаг красный дважды → откати свой коммит (`git revert`), запиши причину в
  `WIDGETS.md` и иди к следующему пункту. `main` не оставлять красным.

## 9. Определение «готово» для каждой волны

- FR / AC / W-INV записаны в спеке до кода; `docs/WIDGETS.md` — статус кейса обновлён.
- Тесты зелёные локально и в CI; тест бюджета проходит.
- Рендер проверен на 200 и 420 px в обеих темах, скриншоты сохранены и сравнены с `docs/prompts/refs/`
  (§6.1): своя подложка, герой-число, живость; без этого волна не закрыта.
- Живой прогон в чат владельца: Telegram принял виджет, запросы (если есть) отвечают < 15 с,
  тестовые сообщения удалены.
- Прод на нужном хэше, бот на поллинге, в логах нет новых ошибок за 10 минут.
- Фолбэк проверен: искусственная ошибка `sendWidget` → пришёл rich-экран.
